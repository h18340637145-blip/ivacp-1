# 产品文档

## 1. 产品定位

Jira 智能票据分析系统面向车载软件质量与中间件团队，将 Jira 缺陷票和飞书项目工作项的人工排查转化为「自动分析 + 人工复核 + 受控回填」闭环。系统从工单描述、评论、图片和 CANtrace 附件中提取证据，生成标准化分析结论，并保留可追溯的运行产物与历史版本。

系统是本地部署的工程工具：浏览器工作数据使用 IndexedDB 保存，规则组服务端配置使用仓库内 JSON 文件轻量持久化；不引入后端数据库、云同步、团队协作或真实 GitHub API。

## 2. 用户与权限

| 角色 | 主要权限 |
|---|---|
| 普通分析员 | 查看统一看板，执行筛票和处理，浏览 Jira / 飞书结果。 |
| 人工复核员 | 审阅 AI 结论，标记通过或驳回，填写修正结论，并显式授权回填。 |
| 系统管理员 | 管理规则组、排序、导入导出和 AutoCycle 配置；维护本地运行环境。 |

登录、会话 Cookie 与基础角色校验由本地认证模块完成。管理类操作和飞书写操作均要求相应授权，前端展示不等同于后端写权限。

## 3. 核心能力

### 3.1 统一规则组看板

首页以规则组为单位展示 Jira 与飞书项目两条来源。每个规则组可配置 Jira JQL、可选 `meegleMql`、车型 CAN 配置、Prompt 和自动周期间隔。看板统一编排来源，但不合并来源数据：Jira 和飞书分别保存自己的任务、快照、结果、历史和校验记录。

Jira 与飞书同次筛选可并行执行。任一来源失败时，另一来源的快照和处理入口仍可用；不得使用历史飞书成功结果替代本次筛选失败。

### 3.2 Jira 筛票与分析

系统按 JQL 拉取 Jira 工单、评论和附件元数据，生成筛票快照。用户可处理最新成功快照，或指定单个 Jira 票号直接分析。处理流程下载 CANtrace / 压缩包和图片附件，解包、解析信号、组织证据、调用 Qwen 模型，再生成分析结论和可选 CAN 图。

每次重新分析都会生成独立结果；旧结论、复核和回填状态进入历史记录，保证可追溯。

### 3.3 飞书项目分析

飞书项目工作项可通过 MQL 自动分配或手工拖拽归入规则组。多规则组命中时，自动分配按 `sortOrder`、再按规则组 `id` 做稳定决策；人工分配不可被自动结果覆盖。MQL 失败写入飞书筛选审计并保留既有自动分配，不修改 Jira 数据。

飞书处理在保存工作项、评论和附件快照后复用共享分析流水线，并为每次运行创建不可变产物目录。完成结果可查看详情、历史、原始数据和白名单内运行产物；可变更经办人或确认重新分析，后者会先归档旧结果。

### 3.4 CANtrace 与证据可视化

系统支持 `.asc` 和 `.blf` 日志，以及 ZIP、分卷压缩包和 7z 等附件。信号 token 会与车型配置中的 `prop`、`getSignals` 或 `setSignals` 匹配，Property ID 映射和时间窗日志摘录均落盘审计。

图表与回放只使用 Step 2 提取并成功匹配的代表信号，候选池、OCR、历史样本或完整车型配置不得补充绘图序列。图表采用共享绝对时间轴、信号独立纵轴和散点形态；用户锁定视口后，可将完整图像作为回填附件。

### 3.5 复核、校验与回填

AI 复核使用 Few-shot 历史样本提供建议，不能解除人工回填门槛。人工通过，或人工驳回并填写正确结论后，才可授权回填。

Jira 评论写回和飞书评论 / 状态流转均是显式操作。飞书评论使用结果标记实现幂等；评论与状态流转分别保存，状态流转失败不会重复发表评论。经办人变更有独立授权、二次读取冲突检查，且不触发其他业务动作。

### 3.6 自动化与运行归档

AutoCycle 先执行当次统一筛选，再按来源汇总分派处理：Jira 仅处理当次最新成功快照；飞书仅在当次 MQL 成功时处理当前 `pending` / `failed` 分配。处理成功响应返回后，浏览器独立写入 IndexedDB；启用 `ENABLE_DOCUPEDIA=1` 时，服务端通过 Next.js `after` 最佳努力归档当前运行日志。归档失败不影响分析结果、复核、回填或后续工单，进程重启也不恢复未完成上传。

### 3.7 远程终端工作台

`/terminal` 提供面向受控目标服务器的 WebSocket 终端界面。用户可选择项目和分支、查看 Git 状态、上传指定类型文件、打包下载、执行配置文件扫描及受限 checkout。敏感 SSH 认证材料仅在 Gateway 进程中使用，浏览器只接收脱敏目标信息。

## 4. 关键业务规则

- Jira 与飞书项目生命周期必须隔离；统一看板只协调展示和派发。
- 分析成功响应和客户端结果持久化不能等待 Docupedia。
- CAN 候选信号用于审计，不可扩展为回放或绘图输入。
- 飞书写回必须经人工复核授权；自动测试不得执行真实写操作。
- 配置 checkout 仅接受 `tools/json/config_*.json` 路径。
- 用户可见文案以中文为主，界面采用暗色工业指令台风格。

## 5. 非目标与约束

系统不提供云端多用户协作、后端关系型数据库、自动审批回填或不受限制的远程命令执行。AI 结论和自动校验均为辅助信息，最终业务判断与对外写回由人工负责。
