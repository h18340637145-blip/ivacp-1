# 全量项目文档集设计规格

## 1. 目标

在 `docs/output-docs/` 生成一套面向产品、开发、测试和运维人员的中文 Markdown 文档，覆盖仓库当前可用功能：Jira 智能票据分析、飞书项目（Meegle）工作项分析、统一规则组看板、人工复核与回填、CANtrace 处理、Docupedia 归档，以及远程终端和配置文件管理。

文档以仓库当前实现和现有 Harness 文档为事实来源；历史记录只用于说明演进背景，不将已废弃或被后续版本收敛的行为描述为现行能力。

## 2. 交付结构

```text
docs/output-docs/
├── README.md
├── 产品文档.md
├── 架构文档.md
├── 流程文档.md
├── 概要设计.md
└── 详细设计.md
```

`README.md` 提供文档目录、目标读者、阅读路径、术语和来源边界。其余五份文档分别对应用户要求的文档类型，避免把同一事实复制到多个位置：产品规则归入产品文档，系统边界归入架构文档，时序归入流程文档，模块职责归入概要设计，数据结构与接口归入详细设计。

## 3. 各文档内容

### 3.1 产品文档

说明产品定位、目标用户和角色、业务范围、核心能力、关键业务规则、非目标和成功标准。功能覆盖规则组管理、Jira / 飞书来源隔离、筛票、分析、可视化、复核回填、自动周期、运行归档与远程终端管理。

### 3.2 架构文档

描述 Next.js App Router、React、TypeScript、Zustand、Dexie / IndexedDB、本地 JSON 配置、Qwen 模型、Jira、飞书项目、Docupedia、附件插件和远程终端网关之间的边界；明确浏览器本地状态与服务端运行产物的职责划分、安全边界、配置项与运行部署方式。

### 3.3 流程文档

用 Mermaid 图和步骤说明统一筛票、Jira 与飞书分析、人工复核和受控回填、Docupedia 异步归档、远程终端连接与受限配置 checkout 的主流程、分支和失败处理。

### 3.4 概要设计

按展示层、客户端状态和持久化、API 适配层、分析流水线、外部集成和运维支撑划分模块；说明每个模块的职责、输入输出、依赖和主要交互，并给出核心状态机与数据流概览。

### 3.5 详细设计

列出主要路由、关键 Store、IndexedDB / 本地文件持久化模型、分析流水线阶段、Jira / 飞书适配方式、结果与历史版本、复核 / 回填幂等机制、CAN 信号约束、异常与权限控制、关键环境变量以及测试策略。

## 4. 一致性与边界

- Jira 与飞书项目分别保存状态和结果，统一看板仅协调两条来源；单一来源失败不得污染另一来源。
- Jira 与飞书成功响应先返回浏览器；Docupedia 归档为受开关控制的异步最佳努力任务，不阻塞结果持久化、复核或回填。
- 本地工作数据使用 IndexedDB；规则组服务端配置使用仓库内 JSON 文件，不引入后端数据库。
- 飞书写回必须经过人工复核授权；评论与状态流转分别记录，流转失败不得导致重复评论。
- CAN 回放与图表只使用 Step 2 提取且配置匹配的代表信号；候选池只作审计。
- 远程终端仅在既有 Gateway 约束内执行；配置 checkout 仅允许 `tools/json/config_*.json`。

## 5. 验收标准

- 六份文件均存在且可由 `README.md` 互相导航。
- 所有内容使用中文 Markdown，标题层级、术语和中英文间距一致。
- 至少包含产品能力、组件边界、端到端流程、核心数据模型 / 接口与安全边界。
- 文档不包含待定占位符，不虚构未实现的功能或 API。
- 完成后更新 `session-handoff.md`，记录文档产出与验证结果。
