# Jira 与飞书项目统一规则组看板设计

## 目标

将现有独立的飞书项目工作台集成到主页 Jira 分析看板。每个规则组可同时筛选 Jira 票和飞书项目工作项；后续处理、AI 分析、人工复核与回填提供一致的业务体验，并保留两种平台的协议差异。

## 范围

- 主页规则组同时支持 JQL 与 MQL 筛选。
- 飞书项目工作项接入主页的筛选、处理、分析、AI 复核、人工复核和回填入口。
- `/meegle` 改为跳转到主页统一规则组看板。
- 保留旧飞书结果详情 URL 的兼容访问。
- 同步更新产品、架构、工作流、时序图和会话交接文档。

本次不引入后端数据库，不改变 Jira 已有行为，不迁移或删除现有 IndexedDB 数据，也不扩展到登录、云同步或真实 GitHub API。

## 方案选择

采用「统一规则组 + 来源适配器」方案。

不采用把两种票据完全混为一张无来源边界的列表：筛选失败、批量处理、附件与回填的语义会变得模糊。也不保留主页仅汇总、再跳转独立飞书工作台的方案：这不能满足统一入口要求。

## 架构

### 统一领域边界

新增标准化来源标识 `IssueSource = "jira" | "meegle"`，并以来源与外部 ID 共同构成票据身份。规则组看板、筛选调度、处理入口、复核授权和展示层只依赖标准化身份及共享状态；外部平台调用由适配器负责。

### 来源适配器

定义 Jira 与飞书项目适配器的公共能力：

- 执行规则组筛选；
- 读取票据详情与附件；
- 建立或恢复处理任务；
- 准备共享 AI 分析输入；
- 生成并提交回填结果。

`JiraIssueAdapter` 负责 JQL、Jira 详情/附件和 Jira 评论回填。`MeegleIssueAdapter` 负责 MQL、飞书工作项/附件和飞书评论回填；其状态流转为飞书平台可选能力，不进入 Jira 适配器。

### 存储策略

保持 Jira 与飞书项目既有 IndexedDB 表物理隔离，避免历史快照、任务、结果、历史记录和校验数据迁移。统一层通过来源适配器访问各自存储；页面层只消费标准化视图模型。

## 用户流程

1. 管理员在规则组内配置 JQL 和/或 MQL。两者均可选；至少配置一种才能执行对应筛选。
2. 首页「一键筛选」并发执行规则组已配置的来源。卡片分别展示 Jira 与飞书项目的运行状态、失败原因和命中数量。
3. 首页「一键处理」按来源读取最新成功快照，分别创建任务，并在统一看板内呈现进度与结果。
4. 处理阶段复用 CANtrace 附件下载、解压、信号解析、AI 推理、证据校验、结果保存和学习记忆。仅详情加载、附件获取、工作项元数据和回填由来源适配器分派。
5. 结果详情使用共享页面骨架，始终显示来源标签；AI 复核和人工复核遵循相同状态与授权门槛。
6. 人工通过，或人工驳回且填写正确结论后，才开放回填。Jira 回填评论及可选 CAN 图；飞书项目先以隐藏标记幂等写评论和可选 CAN 图，再按用户选择执行状态流转。

## 错误处理与幂等性

- Jira 与飞书项目的筛选、处理、回填错误必须来源隔离：任一来源失败不修改另一来源的快照、任务或结果。
- Jira 与飞书项目均保留各自的超时、取消和重试状态。
- 飞书项目评论与状态流转分别持久化。评论成功、状态流转失败时，保存该状态并禁止重复评论；后续仅可重试状态流转。
- 未配置某来源时，不创建该来源的任务，也不将其显示为失败。

## 页面与路由

- 主页规则组卡片展示 Jira 与飞书项目两个来源区块，显示数量、最近筛选状态以及对应处理入口。
- 票据卡片和结果详情显示来源标签；来源决定具体外部链接和回填实现，不改变共享复核操作。
- `/meegle` 重定向至主页统一看板。飞书项目结果详情路由继续可访问，用于旧链接和历史数据。

## 验收与测试

- 双来源均配置时，JQL 与 MQL 并发执行并分别落盘。
- 单来源筛选失败时，另一来源的成功结果保持可处理。
- 处理、详情、复核和回填根据来源分派到正确适配器。
- 人工复核未满足授权条件时，两种来源都不得回填。
- 飞书项目评论幂等；状态流转失败不重复评论。
- `/meegle` 访问后跳转至主页统一规则组看板。
- Jira 既有筛选、处理和评论回填回归测试继续通过。
