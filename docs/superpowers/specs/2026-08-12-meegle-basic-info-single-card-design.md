# 飞书工单基本信息单卡片布局设计

## 背景

飞书工单详情页当前在「基本信息」区域为每个字段绘制独立卡片。字段数量增加后，重复的边框、背景和内边距会割裂阅读路径，也会占用过多纵向空间。

本次调整只改变基本信息的视觉组织方式，不修改工单数据、字段顺序、接口协议或其他详情区块。

## 目标

- 「基本信息」只保留一个外层卡片。
- 所有属性和经办人放入同一个单列键值列表。
- 用户可以沿页面纵向连续扫描字段，不受重复小卡片干扰。
- 长字段值和窄屏布局保持可读。

## 非目标

- 不修改「全部字段」「描述」「评论 / 备注」的布局。
- 不调整字段筛选、排序或值格式化逻辑。
- 不修改飞书接口、IndexedDB 数据或分析流程。
- 不新增折叠、搜索、编辑等交互。

## 布局设计

「基本信息」继续使用现有 `Section` 作为唯一外层卡片。卡片内部采用单列键值列表：

- 每个属性占一行。
- 左侧显示字段名，右侧显示字段值。
- 字段名列使用固定宽度和次级文字颜色。
- 字段值列占用剩余空间，保留现有 `pre-wrap` 和任意位置换行能力。
- 相邻行之间只使用一条细分隔线。
- 每行不再设置独立背景、边框、圆角或外边距。
- 经办人作为列表最后一行，与属性字段使用相同结构和样式。

桌面端字段名列保持统一宽度。窄屏下缩小字段名列宽，字段值继续换行；不切换为独立卡片，也不隐藏内容。

## 组件边界

改动限定在 `components/meegle/MeegleWorkItemDetail.tsx` 的 `MeegleBasicInfo` 及其专用样式：

- `MeegleBasicInfo` 负责把 `attributes` 和 `assigneeRole` 转换为键值行。
- `Section`、`displayValue()` 和数据加载逻辑保持不变。
- 其他详情组件继续复用现有 `fieldStyle`，避免本次布局变更影响其他区块。

## 状态与异常

- 空值继续通过 `displayValue()` 显示为 `--`。
- 没有经办人时继续显示「未指定」。
- 属性为空时仍显示经办人行，确保基本信息卡片不是空容器。
- 对象或数组值继续使用格式化 JSON，并在值列内换行。

## 验证

- 扩展飞书详情 UI 静态检查，要求基本信息使用单一卡片和键值行布局。
- 静态检查禁止 `MeegleBasicInfo` 继续复用逐字段的 `fieldStyle`。
- 运行飞书详情、同构 UI、TypeScript、ESLint 和生产构建检查。
- 浏览器验证桌面宽度与窄屏宽度下的字段对齐、换行和外层卡片数量。

## 验收标准

- 「基本信息」区域只有一个可见外层卡片。
- 所有属性和经办人都显示在该卡片中。
- 每个字段不再呈现为独立小卡片。
- 字段名与字段值按单列键值列表对齐。
- 长内容可以换行，窄屏不出现水平溢出。
- 其他详情区块的结构和行为不变。
