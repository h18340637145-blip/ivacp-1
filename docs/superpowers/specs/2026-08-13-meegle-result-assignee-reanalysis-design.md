# 飞书项目结果页经办人与重新分析设计

## 背景

飞书项目当前票的经办人修改入口位于标准工作项详情页，但分析员在完成结果页复核、回填时仍需要离开该页面操作。结果页也缺少对当前票发起下一次分析的入口。

## 目标

在 `/meegle/issues/{workItemId}/result?assignmentId={assignmentId}` 中提供两项当前票操作：

1. 从当前飞书项目的完整成员目录中模糊搜索并修改经办人。
2. 重新分析当前票，同时保留当前结果为历史版本。

## 非目标

- 不改变 Jira 结果页或 Jira 经办人逻辑。
- 不在浏览器之外新增数据库或云端同步。
- 不自动写入评论、状态流转或飞书项目经办人；经办人修改始终需要用户明确确认。
- 不删除历史结果、快照、任务或运行产物。

## 方案比较

### 方案 A：结果页复用既有经办人控件与 Process Store（采用）

结果页嵌入现有 `MeegleAssigneeControl`，并将当前工作项的 `detailReceipt`、经办人角色和成员传入。重新分析直接调用 `meegleProcessStore.processAssignment(assignment, group)`。

优点：成员目录、模糊搜索、目标绑定授权、二次读取冲突校验，以及快照/历史保存均复用已有实现；不增加新的写入通道。

缺点：结果页在无新鲜详情凭据时需先读取当前工作项详情以获得控件所需数据。

### 方案 B：在结果页重写经办人 API 与分析请求

优点：结果页可以完全独立。

缺点：会复制安全校验和生命周期逻辑，容易使评论、流转、经办人与分析结果产生不一致。拒绝采用。

## 交互设计

结果页顶部增加「当前票操作」区：

- 「修改经办人」展示当前经办人和搜索输入框。输入姓名、邮箱或用户 ID 后，按既有防抖逻辑查询当前项目完整人员目录；选择候选人后显示确认按钮。
- 确认经办人修改时，复用目标绑定的短时授权与服务端二次读取。若当前经办人已被其他用户修改，页面提示刷新后重试；操作不会触发评论、流转、复核或重新分析。
- 「重新分析」弹出确认，提示会保留当前结论为历史版本。确认后禁用重复操作，调用当前 assignment 的分析生命周期。
- 重新分析开始后，当前已完成结果继续可查看；新 run 成功后刷新为最新结果，旧 task/result 通过现有 history 表保留。失败时保留当前结果，并显示本次失败状态和错误。

## 数据流与安全边界

```text
结果页
  ├─ 读取当前 assignment、snapshot、task、result
  ├─ 读取当前工作项详情 → detailReceipt + assigneeRole
  │    └─ MeegleAssigneeControl → /api/meegle/users（模糊搜索）
  │                             → /api/meegle/authorize → /api/meegle/assignee
  └─ 重新分析确认 → processAssignment(assignment, ruleGroup)
       ├─ 归档旧 result 为 MeegleAnalysisHistory
       ├─ 创建新 snapshot/task/runId
       └─ /api/issues/process → 新 result 成为 latestResultId
```

经办人 API 继续验证项目、工作项类型、工作项 ID、经办人角色、当前成员集合和详情版本。重新分析只使用本地 assignment 绑定的规则组，且调用既有 `runningIds` 去重。两项操作均不接受客户端提供的跨票身份。

## 错误处理

- 详情或成员目录加载失败：显示可重试错误，不显示可提交的经办人修改确认。
- 用户搜索无匹配：展示「未找到匹配人员」，不发送写请求。
- 授权失效或目标状态变化：显示具体错误并重新读取详情。
- 重新分析请求失败：由既有 Process Store 将新尝试记录为 failed，同时保持上一个 completed result 可读。
- 新 run 成功但浏览器持久化中断：既有成功产物自动恢复机制继续生效。

## 验收标准

1. 结果页能查看并修改当前票经办人，候选来自当前项目完整成员目录，支持姓名、邮箱和用户 ID 模糊匹配。
2. 经办人修改使用既有授权与并发冲突保护，且不触发评论、流转或重新分析。
3. 结果页可以明确确认后重新分析当前票，分析期间禁止重复提交。
4. 重新分析后旧结果进入历史，新结果成为当前结果；失败不丢失旧结果。
5. 相关 UI、经办人安全链路、飞书结果生命周期、TypeScript 检查和生产构建通过。
